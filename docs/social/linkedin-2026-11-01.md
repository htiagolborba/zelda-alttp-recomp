## Post text

I'm bringing A Link to the Past into a miniature 3D world on macOS — and my latest milestone now goes beyond Link's opening room.

I've been building a Godot presentation layer around the game's existing reverse-engineered C implementation. My focus is preserving the gameplay logic while changing how that world is rendered.

The side-by-side images show actual running gameplay: the original 2D renderer on the left and my 3D integration on the right, captured at the same native simulation state.

Since my last update, I've expanded the project with:

• Connected outdoor presentation: terrain, paths, foliage, water and house details.
• Animated Link and pot carrying driven by native game state.
• Native PCM audio delivery and isolated save handling.
• Tested Game Over recovery, continuing into the 3D scene and moving again.
• Reusable source-map tools and repeatable regression routes to make further development more efficient.

My stack: C, GDScript, Python, Godot and custom shaders.

One engineering decision has shaped the project: I keep the C simulation authoritative for movement, collision, inventory and game state. Godot handles the presentation. That lets me compare the new renderer against the original behavior as I develop it.

This is still an ongoing private macOS prototype. My next milestone is expanding connected outdoor areas and integrating more actors and interactions. The public stable download still uses the original 2D graphics.

Credit matters: the reverse-engineered C foundation comes from snesrev/zelda3, and the original game and visual resources belong to Nintendo. My work is the adaptation, integration, presentation systems and development tooling, with AI-assisted development.
